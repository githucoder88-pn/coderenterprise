## 2025-02-14 - Replace custom timing safe comparison and prevent timingSafeEqual Buffer length crashes
**Vulnerability:** The CSRF token validation logic used a custom, bitwise comparison loop that is susceptible to timing attacks due to V8 JavaScript engine optimizations. Furthermore, `timingSafeEqual` in Node.js throws exceptions when given Buffers of different lengths, which can be triggered by attackers supplying invalid input and lead to Denial of Service (DoS) by crashing the Node.js process.
**Learning:** Custom implementations of cryptographic checks in JavaScript can easily be undermined by JIT optimizations (like early exit or varying instruction execution times). Using Node.js's native `crypto.timingSafeEqual` solves this, but it requires that both `Buffer` parameters have exactly the same byte length.
**Prevention:** Always use `node:crypto.timingSafeEqual` instead of manual bitwise checks for constant-time comparisons. Before calling `timingSafeEqual`, assert that the `.length` of both input Buffers is exactly equal to prevent runtime exceptions.
