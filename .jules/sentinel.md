## 2024-05-15 - Node.js crypto.timingSafeEqual Length Mismatch Vulnerability
**Vulnerability:** Node's `crypto.timingSafeEqual` will throw an unhandled `TypeError` or `RangeError` ("Input buffers must have the same byte length") if the buffers passed have different lengths. Attackers can intentionally provide strings of different lengths (e.g. invalid hashes or MACs) to cause the application to crash, resulting in a Denial of Service (DoS), or use the resulting thrown error timing difference in a side-channel attack.
**Learning:** Node.js native `crypto.timingSafeEqual` strictly enforces that both buffers must be the same length to ensure execution time is constant for that given length.
**Prevention:** Always convert values to `Buffer` and explicitly check `buffer1.length !== buffer2.length` prior to calling `timingSafeEqual`. To maintain constant time across different lengths, perform a dummy comparison (e.g., `timingSafeEqual(buffer2, buffer2)`) when lengths differ before returning `false`.
