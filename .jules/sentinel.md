## 2024-06-25 - Safe Buffer Conversion for Cryptographic Comparison
**Vulnerability:** A JavaScript-based bitwise string comparison for CSRF tokens was used, which is vulnerable to V8 engine optimizations and potential timing attacks. The initial patch introduced a critical bypass by forcing a 'hex' encoding on `Buffer.from(signature, 'hex')`. If the underlying signature was not purely hex, Node.js would silently truncate it, causing empty buffer comparisons to pass and bypassing CSRF protections entirely. Additionally, it introduced a DoS vector by allocating large Buffers before checking their lengths.
**Learning:** When using `crypto.timingSafeEqual` in Node.js, it is critical to compare Buffer lengths *before* calling the function to avoid `TypeError` and DoS vulnerabilities via unhandled exceptions. More importantly, when converting dynamic strings into Buffers, **never assume a specific encoding (like 'hex') unless it is absolutely guaranteed**. If the encoding is incorrect, `Buffer.from()` will truncate the input silently, leading to a critical security bypass (e.g. comparing two empty buffers). Omit the encoding argument to default to UTF-8 and safely capture the exact string bytes.
**Prevention:** Always maintain a strict length validation (`if (sigBuf.length !== expectedSigBuf.length) return false;`) right before calling `timingSafeEqual`. When converting strings for timing-safe operations where the format isn't strictly controlled, omit the encoding argument (i.e. use `Buffer.from(signature)`) so the buffer safely defaults to utf-8.
